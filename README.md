# claude-crew

여러 클로드에게 동시에 일을 시키고, 진행 상황을 2D 픽셀 오피스 한 화면에서 지켜보는 개인 비서입니다.

빈 책상을 누르면 사람을 부르고, 그 사람과 대화하면서 일을 시킵니다. 쓰면 쓸수록 여러분이
무슨 일을 얼마나 하는지, 그 일을 어떻게 하기를 원하는지 알게 됩니다.

**여러분의 Claude 구독으로 동작합니다.** API 키를 쓰지 않고, 앱이 토큰을 저장하거나 전송하지도
않습니다. 여러분 PC 에 이미 로그인된 Claude Code 를 자식 프로세스로 실행할 뿐입니다.

---

## 설치

PowerShell 을 열고 한 줄:

```powershell
irm https://raw.githubusercontent.com/Yongbeen01/claude-crew/main/scripts/install.ps1 | iex
```

Node 와 Claude Code 가 없으면 알아서 설치하고, 바탕화면 바로가기를 만들고, Claude 로그인까지
안내한 뒤 실행합니다. 다음부터는 **바탕화면의 claude-crew 아이콘**으로 열면 됩니다.

필요한 것은 Windows 10/11 과 **Claude 유료 구독**(Pro / Max / Team) 뿐입니다.

**GitHub 계정은 필요 없습니다.** 설치도 업데이트도 로그인 없이 받아 갑니다. Node, git,
Claude Code 도 없으면 설치 과정에서 알아서 챙깁니다.

### 업데이트

다시 설치할 필요 없습니다. 새 버전이 나오면 앱 위쪽에 띠가 뜨고, **받기**를 누른 다음 앱을 다시
시작하면 끝입니다. 업무 이력·지침·유형 설정은 `%USERPROFILE%\.claude-crew` 에 따로 있어서
업데이트가 지우지 않습니다.

## 네 가지 유형

| | 하는 일 |
| --- | --- |
| **디자이너** | 발표 자료를 만듭니다. 목차를 먼저 보여주고 동의를 받은 뒤 파일을 만듭니다. |
| **토끼** | 할 일과 시간을 관리합니다. 아래 설명 참고. |
| **마법사** | 무슨 일이든 맡습니다. 여러분이 연결해 둔 외부 도구(슬랙·드라이브 등)도 씁니다. |
| **표고버섯** | 표와 엑셀을 다룹니다. 숫자를 지어내지 않고, 계산하면 반드시 검산해서 알려줍니다. |

유형마다 성격(system.md)과 스킬이 폴더 하나로 정의되어 있습니다. 왼쪽 위 **유형** 버튼에서
그 자리에서 고칠 수 있고, **다음에 부르는 사람부터** 반영됩니다.

### 토끼는 이렇게 씁니다

1. 토끼를 부르면 먼저 "오늘 할 일이 뭐예요?" 하고 물어봅니다.
2. 할 일을 알려주면 항목별로 몇 시간 걸릴지 확인합니다. 시간까지 같이 주면 이 단계는 넘어갑니다.
3. 정리된 목록을 보여주고 "뭐부터 하실래요?" 하고 묻습니다.
4. 고르면 타이머가 돕니다. **1시간 전 · 30분 전 · 15분 전 · 종료** 시점에 토끼가 말을 겁니다.
5. 끝났다고 하면 실제로 걸린 시간까지 기록합니다.

시간을 세는 건 앱이지 토끼가 아닙니다. 그래서 브라우저 탭을 닫아도 알림이 옵니다.

## 쓸수록 배웁니다

일이 끝날 때마다 무슨 일을 얼마나 걸려 했는지가 쌓입니다. 같은 일이 반복되면 왼쪽 **자주 하는 일**
에 카드로 나타납니다.

카드를 사람에게 **끌어다 놓으면**, 그 사람은 지난번까지 정리된 방식과 평균 소요 시간을 들고
시작합니다. 다시 설명할 필요가 없습니다. 이름표 밑에는 그 업무 이름이 붙습니다.

"이렇게 해주세요" 라고 알려준 것은 그 일의 지침으로 남습니다. 예를 들어 메일 정리를 하면서
"광고메일은 읽지 말고 바로 지워주세요" 라고 하면, 다음부터 묻지 않습니다.

## 화면 보는 법

- **이름표 밑 한 줄** — 지금 무슨 일을 하는 중인지. 업무 카드가 붙어 있으면 그 업무 이름.
- **모니터 색** — 초록빛은 작업 중, 빨강은 승인 대기, 회색은 쉬는 중. 자면 `z` 가 올라갑니다.
- **승인 기다리는 중** — 파일을 쓰거나 명령을 실행하려면 허락을 받습니다. 읽기·검색은 묻지 않습니다.
  매번 누르기 번거로우면 그 사람에게 **알아서 하게 두기**를 켜 주세요.
- **작업 과정 지켜보기** — 켜면 브라우저를 실제로 띄워서 하는 일이 눈에 보입니다.
- **남은 한도** — 여러분 구독의 남은 사용량입니다. 사람을 여러 명 앉히면 그만큼 빨리 줄어듭니다.

머리를 좌우로 문질러 보세요.

## 데이터

전부 이 PC 안에만 있습니다. 어디로도 보내지 않습니다.

```
%USERPROFILE%\.claude-crew\
  personas\<유형>\      유형의 성격과 스킬 (설치 때 복사되고, 이후 여러분 것입니다)
  jobs\<업무>\          업무별 누적 지침과 실행 이력
  sessions\<사람>\      사람마다의 작업 폴더 — 첨부 파일과 만든 결과물
  worklog.jsonl         완료 기록 원장
  tasks.json            오늘 할 일과 타이머
```

PC 를 바꿀 땐 이 폴더를 통째로 복사하면 그대로 이어집니다.

## 만든 방식

의존성이 하나도 없습니다 (`node:http` + 손으로 그린 캔버스). 그래서 업데이트가 파일 교체와
재시작으로 끝납니다.

- 사람 한 명 = `claude` CLI 자식 프로세스 하나. stdin 으로 턴을 계속 밀어 넣습니다.
- 세션이 앱에 데이터를 돌려주는 통로는 로컬 MCP 서버 하나(`/mcp/<토큰>`)입니다.
- 도구 승인은 `PreToolUse` 훅의 HTTP 응답을 붙잡아 두고, 화면에서 누른 결정을 응답 바디로
  돌려주는 방식입니다.

이 세 가지를 포함해 설계 전에 실제로 돌려서 확인한 것들은 [scripts/spike/README.md](scripts/spike/README.md)
에 정리해 뒀습니다. 특히 `PermissionRequest` 훅이 헤드리스에서 아예 불리지 않는다는 점은
같은 함정을 다시 밟지 않도록 표까지 남겼습니다.

```bash
npm start          # 실행
npm run spike      # 설계 전제 3가지 재검증
```

### 고치고 배포하기

```
개발용                            배포                    사용자
Documents\claude-crew  ──push──▶  GitHub main  ──받기──▶  %LOCALAPPDATA%\claude-crew
```

수정은 개발용 사본에서만 합니다. 배포는 `git push` 하나가 전부입니다 — 빌드도, 배포
스크립트도 없습니다. push 하면 `check` 워크플로가 문법·BOM 규칙·시크릿·데이터 경로를 봅니다.

사용자 쪽은 부팅 시와 6시간마다 원격을 확인하고, 새 버전이 있으면 화면 위에 띠를 띄웁니다.
**받기** → 앱 재시작이면 끝입니다.

주의할 것 두 가지:

- **사본이 둘입니다.** 바탕화면 아이콘과 자동 업데이트는 `%LOCALAPPDATA%\claude-crew` 를
  봅니다. 개발용에서 `npm start` 하면 포트 4320 이 충돌하니, 구동본을 먼저 멈추세요
  (`scripts\launch.ps1 -Stop`).
- **설치 한 줄은 CDN 캐시를 탑니다.** `raw.githubusercontent.com` 은 약 5분 캐시라
  push 직후의 *신규 설치*는 이전 버전을 받을 수 있습니다. 이미 설치된 사람들의 자동
  업데이트는 git 프로토콜이라 즉시 반영됩니다.

`.ps1` 파일을 건드릴 땐 BOM 규칙을 지켜야 합니다 — `install.ps1` 은 BOM이 **없어야** 하고
(`irm | iex` 가 BOM을 명령어로 읽습니다), `-File` 로 실행되는 나머지는 BOM이 **있어야**
합니다(PowerShell 5.1 이 ANSI 로 읽어 한글 파싱이 깨집니다). CI가 이 둘을 확인합니다.
