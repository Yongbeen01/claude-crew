# claude-crew

여러 클로드에게 동시에 일을 시키고, 진행 상황을 2D 픽셀 오피스 한 화면에서 지켜보는 개인 비서입니다.

빈 책상을 누르면 사람을 부르고, 그 사람과 대화하면서 일을 시킵니다. 쓰면 쓸수록 여러분이
무슨 일을 얼마나 하는지, 그 일을 어떻게 하기를 원하는지 알게 됩니다.

**여러분의 Claude 구독으로 동작합니다.** API 키를 쓰지 않고, 앱이 토큰을 저장하거나 전송하지도
않습니다. 여러분 PC 에 이미 로그인된 Claude Code 를 자식 프로세스로 실행할 뿐입니다.

---

## 설치

PowerShell 을 열고 한 줄:

```powershell
irm https://raw.githubusercontent.com/Yongbeen01/claude-crew/main/scripts/install.ps1 | iex
```

Node, git, Claude Code 가 없으면 알아서 챙기고, 바탕화면 바로가기를 만들고, Claude 로그인까지
안내한 뒤 실행합니다. 다음부터는 **바탕화면의 claude-crew 아이콘**으로 열면 됩니다.

필요한 것은 Windows 10/11 과 **Claude 유료 구독**(Pro / Max / Team) 뿐입니다.
GitHub 계정도, 관리자 권한도 필요 없습니다 — 설치 프로그램 대신 무설치본을 받으므로
권한 상승 창이 뜨지 않습니다.

> **왜 `.bat` 더블클릭이 아닌가.** `scripts/claude-crew-install.bat` 도 같이 들어 있고
> 내용은 동일하지만, **Windows 11 의 Smart App Control 이 켜져 있으면 차단됩니다**
> (`액세스가 거부되었습니다`, 코드 5 — 관리자 권한으로도 안 풀립니다). 인터넷에서 받은
> 서명 없는 실행 파일이기 때문이고, 넘으려면 코드 서명 인증서가 필요합니다.
> 위의 한 줄은 다운로드된 파일이 아니라 사용자가 직접 입력한 명령이라 이 정책에 걸리지
> 않습니다. 그래서 이쪽이 기본입니다.

### 업데이트

**아무것도 안 하셔도 됩니다.** 30분마다 새 버전이 있는지 보고, 있으면 알아서 받아서 앱을 다시
켭니다. 앉아 있던 사람들은 나눈 대화 그대로 자리로 돌아오고, 일하다 끊긴 사람은 이어서 합니다.
일하는 사람이 하나라도 있으면 끝날 때까지 기다리므로, 하던 일이 사라지는 일은 없습니다.

업무 이력·지침·유형 설정은 `%USERPROFILE%\.claude-crew` 에 따로 있어서 업데이트가 지우지
않습니다. 알아서 받는 게 싫으면 `config.json` 에 `"autoUpdate": false` 를 넣으세요 — 그러면
예전처럼 띠가 뜨고 **받기**를 눌러야 합니다.

## 다섯 가지 유형

| | 하는 일 |
| --- | --- |
| **디자이너** | 발표 자료를 만듭니다. 목차를 먼저 보여주고 동의를 받은 뒤 파일을 만듭니다. |
| **토끼** | 할 일과 시간을 관리합니다. 아래 설명 참고. |
| **마법사** | 무슨 일이든 맡습니다. 여러분이 연결해 둔 외부 도구(슬랙·드라이브 등)도 씁니다. |
| **표고버섯** | 표와 엑셀을 다룹니다. 숫자를 지어내지 않고, 계산하면 반드시 검산해서 알려줍니다. |
| **영화감독** | 영상을 봅니다. 유튜브·틱톡 링크나 영상 파일을 주면 화면을 시간대별로 보고, 말은 받아 적어서 무슨 내용인지 알려줍니다. |

유형마다 성격(system.md)과 스킬이 폴더 하나로 정의되어 있습니다. 대화창 위 **유형** 버튼에서
그 자리에서 고칠 수 있고, **다음에 부르는 사람부터** 반영됩니다.

### 모델과 생각 깊이

같은 유형이라도 오늘 맡은 일에 따라 필요한 머리가 다릅니다.

- **유형 화면**에서 그 유형의 **기본값**을 정합니다 (예: 영화감독은 opus · 생각 낮음).
- **대화창 아래**에서 그 **사람 한 명만** 바꿉니다. 바꿔도 하던 이야기는 그대로 이어집니다.
- 일하는 중에는 바꾸지 않습니다. 하던 답이 사라지기 때문에, 끝난 뒤에 바꿔 주세요.

### 영화감독을 처음 부르면

영상을 다루는 도구(ffmpeg·yt-dlp·받아쓰기 모델)를 그때 한 번 받습니다. **처음 한 번만
400MB쯤, 첫 받아쓰기에 240MB쯤** 더 받고, 그 뒤로는 안 받습니다. 영화감독을 부르지 않으면
아무것도 받지 않습니다.

받아쓰기는 **이 컴퓨터 안에서** 돕니다 — 어디로도 소리를 보내지 않고, API 키도 쓰지 않습니다.

영상 파일을 붙이면 화면과 말을 모두 봅니다. 링크는 유튜브가 잘 되고, **틱톡은 화면만**
봅니다(소리를 받아올 길이 막혀 있습니다). 틱톡에서 사람인지 확인하는 퍼즐이 뜨면 눈앞의
브라우저에서 한 번만 맞춰 주세요 — 그 다음부터는 안 뜹니다.

### 토끼는 이렇게 씁니다

1. 토끼를 부르면 먼저 "오늘 할 일이 뭐예요?" 하고 물어봅니다.
2. 할 일을 알려주면 항목별로 몇 시간 걸릴지 확인합니다. 시간까지 같이 주면 이 단계는 넘어갑니다.
3. 정리된 목록을 보여주고 "뭐부터 하실래요?" 하고 묻습니다.
4. 고르면 타이머가 돕니다. **1시간 전 · 30분 전 · 15분 전 · 종료** 시점에 토끼가 말을 겁니다.
5. 끝났다고 하면 실제로 걸린 시간까지 기록합니다.

시간을 세는 건 앱이지 토끼가 아닙니다. 그래서 브라우저 탭을 닫아도 알림이 옵니다.

## 쓸수록 배웁니다

일이 끝날 때마다 무슨 일을 얼마나 걸려 했는지가 쌓입니다. 같은 일이 반복되면 왼쪽 **자주 하는 일**
에 카드로 나타납니다.

카드를 사람에게 **끌어다 놓으면**, 그 사람은 지난번까지 정리된 방식과 평균 소요 시간을 들고
시작합니다. 다시 설명할 필요가 없습니다. 이름표 밑에는 그 업무 이름이 붙습니다.

"이렇게 해주세요" 라고 알려준 것은 그 일의 지침으로 남습니다. 예를 들어 메일 정리를 하면서
"광고메일은 읽지 말고 바로 지워주세요" 라고 하면, 다음부터 묻지 않습니다.

## 내보내기 — 오른쪽 문

사람을 끌어서 **오른쪽 문**에 놓으면 그 세션을 끝냅니다. 정말 끝낼 것인지 한 번 묻고, 예를
누르면 그 사람은 자리에서 울면서 짐을 싸고, 상자를 들고 복도를 걸어 나갑니다.

걸어 나가는 동안 그 사람은 **이번에 알게 된 것을 남깁니다.** 다음 사람이 같은 일을 맡을 때
쓸모 있는 것만 추려서 두 군데에 들어갑니다.

- 그 **업무의 지침** — 다음에 그 일 카드를 끌어다 놓으면 같이 따라갑니다.
- 그 **유형의 스킬** — 그 유형으로 부르는 모든 사람이 앞으로 갖고 시작합니다.

이번 한 번만 해당하는 것(파일 이름, 오늘 날짜, 이번 수치)은 남기지 않습니다. 남길 것이 없으면
아무것도 쓰지 않습니다. 오른쪽 아래 **퇴근시키기** 버튼도 같은 절차를 밟습니다.

나간 사람은 돌아오지 않습니다. 세션은 되살릴 수 없습니다.

## 오른쪽 구역 — 지금 이 컴퓨터에 열려 있는 것들

방은 두 구역입니다. 왼쪽은 위에서 설명한 클로드들이고, **오른쪽은 여러분이 지금 열어 둔
창들**입니다. 창 하나가 사람 하나이고, 브라우저는 **탭 하나가 사람 하나**입니다. 이름은 그
파일 이름, 프로그램 이름, 탭 제목 그대로입니다. (왼쪽의 유형들과는 아무 상관 없는, 그냥
사람들입니다.)

한 가지 일에는 보통 창이 여러 개 붙습니다. 그 창들을 **한 테이블에 모으면** 그게 그룹입니다.

- 사람을 끌어다 다른 테이블에 놓으면 그 그룹으로 옮겨집니다. 테이블 밖 아래쪽 대기 구역에
  놓으면 어느 그룹에도 속하지 않습니다.
- 빈 바닥에 놓으면 새 테이블이 생깁니다.
- 그룹 이름은 이름표를 눌러 직접 고치거나, 왼쪽 **오늘** 할 일을 끌어다 놓으면 그 할 일
  이름이 됩니다.
- 테이블의 **열기 / 숨기기**를 누르면 그 그룹의 창이 한 번에 올라오고, 한 번 더 누르면 한
  번에 내려갑니다. 일을 시작할 때 한 번, 끝날 때 한 번입니다.
- 사람을 누르면 그 창(브라우저면 그 탭까지)이 바로 앞으로 나옵니다.

창을 닫았다가 다시 열어도 원래 있던 테이블로 돌아옵니다. 숨기기는 **최소화**입니다 — 작업
표시줄에 그대로 남으니 손으로도 언제든 되돌릴 수 있습니다. 다른 그룹의 창이 섞여 있는
브라우저 창은 숨기지 않습니다.

> 이 구역은 **Windows 에서만** 나옵니다. 다른 OS 에서는 방에 왼쪽 구역만 있습니다.
> 탭을 하나하나 읽는 데는 Windows 의 UI Automation 을 씁니다.

## 화면 보는 법

- **이름표 밑 한 줄** — 지금 무슨 일을 하는 중인지. 업무 카드가 붙어 있으면 그 업무 이름.
- **모니터 색** — 초록빛은 작업 중, 빨강은 승인 대기, 회색은 쉬는 중. 자면 `z` 가 올라갑니다.
- **승인 기다리는 중** — 파일을 쓰거나 명령을 실행하려면 허락을 받습니다. 읽기·검색은 묻지 않습니다.
  매번 누르기 번거로우면 그 사람에게 **알아서 하게 두기**를 켜 주세요.
- **작업 과정 지켜보기** — 켜면 브라우저를 실제로 띄워서 하는 일이 눈에 보입니다.
- **남은 한도** — 여러분 구독의 남은 사용량입니다. 사람을 여러 명 앉히면 그만큼 빨리 줄어듭니다.

머리를 좌우로 문질러 보세요.

## 만든 방식

의존성이 하나도 없습니다 (`node:http` + 손으로 그린 캔버스). 그래서 업데이트가 파일 교체와
재시작으로 끝납니다.

- 사람 한 명 = `claude` CLI 자식 프로세스 하나. stdin 으로 턴을 계속 밀어 넣습니다.
- 세션이 앱에 데이터를 돌려주는 통로는 로컬 MCP 서버 하나(`/mcp/<토큰>`)입니다.
- 도구 승인은 `PreToolUse` 훅의 HTTP 응답을 붙잡아 두고, 화면에서 누른 결정을 응답 바디로
  돌려주는 방식입니다.
- 열린 창 목록은 오래 살아 있는 PowerShell 자식 하나([scripts/desktop-host.ps1](scripts/desktop-host.ps1))
  가 JSON 줄로 답합니다. 폴링마다 `powershell.exe` 를 새로 띄우면 매번 프로세스 시작에만
  0.6초가 듭니다. 브라우저 탭은 UI Automation 으로 읽되, 페이지 안의 탭 위젯은
  조상에 Document 가 있는지로 걸러냅니다 — 없으면 사이트의 탭 바가 사람으로 둔갑합니다.

이 세 가지를 포함해 설계 전에 실제로 돌려서 확인한 것들은 [scripts/spike/README.md](scripts/spike/README.md)
에 정리해 뒀습니다. 특히 `PermissionRequest` 훅이 헤드리스에서 아예 불리지 않는다는 점은
같은 함정을 다시 밟지 않도록 표까지 남겼습니다.

```bash
npm start          # 실행
npm run spike      # 설계 전제 3가지 재검증
```

### 고치고 배포하기

```
개발용                            배포                     사용자
Documents\claude-crew  ──push──▶  GitHub main  ──알아서──▶  %LOCALAPPDATA%\claude-crew
```

수정은 개발용 사본에서만 합니다. 배포는 `git push` 하나가 전부입니다 — 빌드도, 배포
스크립트도 없습니다. push 하면 `check` 워크플로가 문법·BOM 규칙·시크릿·데이터 경로를 봅니다.

사용자 쪽은 켤 때와 **30분마다** 원격을 확인하고, 새 버전이 있으면 묻지 않고 받아서 스스로
다시 켭니다. 사람이 눌러야 할 것은 없습니다. 단 **일하는 사람이 하나라도 있으면 기다립니다** —
대화는 다시 켜져도 그대로 돌아오지만 지금 돌고 있는 턴은 못 살리기 때문입니다.

> push 는 곧 배포입니다. 반쯤 만든 것을 올리면 30분 안에 남의 화면에서 돕니다.

주의할 것 두 가지:

- **사본이 둘입니다.** 바탕화면 아이콘과 자동 업데이트는 `%LOCALAPPDATA%\claude-crew` 를
  봅니다. 개발용에서 `npm start` 하면 포트 4320 이 충돌하니, 구동본을 먼저 멈추세요
  (`scripts\launch.ps1 -Stop`).
- **설치 한 줄은 CDN 캐시를 탑니다.** `raw.githubusercontent.com` 은 약 5분 캐시라
  push 직후의 *신규 설치*는 이전 버전을 받을 수 있습니다. 이미 설치된 사람들의 자동
  업데이트는 git 프로토콜이라 즉시 반영됩니다.

`.ps1` 파일을 건드릴 땐 BOM 규칙을 지켜야 합니다 — `install.ps1` 은 BOM이 **없어야** 하고
(`irm | iex` 가 BOM을 명령어로 읽습니다), `-File` 로 실행되는 나머지는 BOM이 **있어야**
합니다(PowerShell 5.1 이 ANSI 로 읽어 한글 파싱이 깨집니다). CI가 이 둘을 확인합니다.
